# Fonte de temperatura de CPU AMD no Windows

Data: 08/11/2026. Pesquisa documental em fontes primárias; nenhuma instalação, execução de SDK, sondagem de hardware ou mudança de política. Complementa [a pesquisa de GPU](windows-gpu-thermal.md), especialmente sua conclusão ampla sobre CPU indisponível.

## Conclusão

**Existe uma candidata oficial adicional que merece validação: o sensor `ADL_PMLOG_TEMPERATURE_CPU = 32` do AMD Display Library (ADL), acessado pelo driver gráfico AMD já instalado.** O identificador consta no [header oficial da AMD](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/display-library/master/include/adl_defines.h). Isso corrige a hipótese de que toda rota AMD necessariamente passa por Ryzen Master/PawnIO/WinRing. A existência do enum não comprova que o driver deste equipamento exponha o sensor, que a leitura identifique o package desejado ou que as permissões permitam consultá-lo sem elevação.

Não há ainda fonte **validada neste equipamento** para CPU °C sob o contrato: processo comum, sem novo driver/serviço, sem instalar software e sem alterar Smart App Control. Manter a métrica indisponível até obter essa prova; não concluir impossibilidade universal. Ter CPU AMD e GPU AMD é condição para investigar o caminho ADL, não evidência de sensor disponível.

## Rotas oficiais examinadas

| Rota | Evidência e limite |
| --- | --- |
| ADL PMLog | O enum oficial inclui CPU °C (32), potência CPU (33) e clock CPU (34). O [tipo de saída](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/display-library/master/include/adl_structures.h) contém `sensors[256]`, cada um com `supported` e `value`. A [API oficial](https://gpuopen-librariesandsdks.github.io/adl/group__OVERDRIVE8API.html) oferece consulta por adaptador e consulta de suporte. Candidata a usar o componente gráfico existente; sem garantia de presença, permissões, unidade/semântica efetiva ou ausência de dependências adicionais no pacote do fornecedor. |
| Ryzen Master Monitoring SDK | A [página AMD](https://www.amd.com/en/developer/ryzen-master-monitoring-sdk.html) confirma temperatura somente leitura para famílias Ryzen/Threadripper suportadas e recomenda `GetCPUParameters` no máximo uma vez por segundo para limitar carga no SMU. O [boletim AMD](https://www.amd.com/en/resources/product-security/bulletin/amd-sb-9020.html) identifica o driver e inclui o Monitoring SDK entre os produtos afetados/mitigados. Fonte real, mas não uma API puramente em modo usuário que dispense componente privilegiado. As páginas consultadas não comprovam acesso sem admin; não inferir que DLL existente resolve a restrição. |
| ADLX | [SystemMetrics](https://gpuopen.com/manuals/adlx/adlx-sdk-references/adlx-interfaces/performance-monitoring/iadlxsystemmetrics/) expõe CPU %, RAM, SmartShift e timestamp; a [extensão 1](https://gpuopen.com/manuals/adlx/adlx-sdk-references/adlx-interfaces/performance-monitoring/iadlxsystemmetrics1/) acrescenta distribuição de potência. Não há CPU °C nessas interfaces. Temperatura da GPU não pode ser relabelada como CPU. A limitação de ADLX não se estende automaticamente ao sensor 32 do ADL. |
| Ryzen AI / xrt-smi | A [documentação oficial XRT](https://xilinx.github.io/XRT/master/html/xrt-smi.html) define a ferramenta para NPUs Ryzen cliente. A [documentação Ryzen AI](https://ryzenai.docs.amd.com/en/1.2/xrt_smi.html) descreve estado, clocks, partições e telemetria da NPU. Não estabelece contrato de temperatura package CPU; o nome Ryzen AI não é prova de tal capacidade. |
| AMD uProf / SMU | O [guia oficial uProf](https://docs.amd.com/r/en-US/57368-uProf-user-guide/4.3.2.2.-MSR-Mode) documenta acesso Windows a MSRs via IOCTL ao driver `AMDPowerProfiler`. A rota não remove a dependência privilegiada. Não foi encontrado contrato público AMD que permita a processo comum ler diretamente o SMU da CPU no Windows sem um intermediário apropriado. |
| OEM / ACPI | Uma interface OEM preexistente e documentada, com sensor CPU explícito e permissão de leitura para usuário comum, seria outra possibilidade condicionada. Nenhuma foi demonstrada. As [zonas térmicas ACPI](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/device-level-thermal-management) são regiões definidas pelo fabricante, não prova automática de temperatura CPU. Não executar comandos SMU ou métodos OEM desconhecidos por tentativa. |

## Próxima prova limitada e critérios de aceite

Se o agente principal fizer a sondagem autorizada, priorizar **somente consultas ADL** pelo componente AMD já instalado em caminho confiável. Consultar suporte e leitura do sensor 32, sem instalar SDK/driver e sem APIs de ajuste, início de log em disco ou mudança de configuração. `ADL2_New_QueryPMLogData_Get` retorna a estrutura, mas a AMD a marca obsoleta por eficiência e recomenda a variante de memória compartilhada quando suportada; uma sonda pontual não define o backend de produção. [Referência ADL](https://gpuopen-librariesandsdks.github.io/adl/group__OVERDRIVE8API.html).

Projetar o resultado antes de imprimir/gravar: categoria da fonte, sucesso/erro, suporte do sensor e validade. Omitir nomes, IDs e caminhos do dispositivo. Para aceitar CPU °C, ainda são necessárias leituras válidas sem elevação, confirmação da unidade e do significado do sensor no pacote aplicável, atualização entre amostras e rejeição de ausência/sentinela. Nenhum `0` artificial deve substituir sensor indisponível. `supported = 0` encerraria essa rota nesse driver; não autoriza instalar outra dependência.

As provas locais previamente relatadas (WMI genérico sem instâncias, ACPI não implementado e famílias conhecidas de drivers opcionais ausentes) não testaram ADL sensor 32. Portanto, não bastam para eliminá-lo. A assinatura do EXE e o Smart App Control permanecem condições independentes; encontrar uma API não garante execução de toda build sem assinatura.

## Sondagem local posterior — 08/11/2026

O agente principal realizou uma consulta somente de leitura pela `atiadlxx.dll` já instalada em System32. `ADL2_Main_Control_Create` inicializou o contexto; `ADL2_Adapter_NumberOfAdapters_Get` e `ADL2_Adapter_AdapterInfo_Get` forneceram os índices reais para a consulta, sem assumir uma sequência de índices. `ADL2_New_QueryPMLogData_Get` estava exportada e cinco consultas retornaram sucesso. Nenhuma informou `supported` para o sensor CPU 32. Assim, não há leitura CPU validada neste driver/equipamento; a candidata foi efetivamente sondada e permanece indisponível. Não houve instalação, elevação ou alteração das proteções. Strings de adaptador/driver e outros campos de PMLog ficaram somente em memória e não foram publicados.

Sanitização desta nota: somente documentação pública, nomes de APIs e categorias/resultados projetados das consultas; sem captura, identificador ou métrica real do equipamento. Revisão textual realizada conforme [sanitização](../../../docs/agents/sanitizacao.md). Pesquisa e sondagem local encerradas; suporte e aceite de CPU °C não foram declarados. Não atribuir percentual global de TR06 a esta pesquisa isolada.
